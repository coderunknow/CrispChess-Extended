# CrispChess Extended v2.3.2-dev4 (prerelease)

This is a development prerelease, **not** the stable v2.3.2 release.

## "Stockfish 16: failed — Bad state: initialize returned with state error"

Desktop releases do not bundle Stockfish: it is GPL-3.0 and CrispChess is MIT.
The built-in Stockfish 16 adapter therefore looks for a Stockfish installed on
the computer. In dev3 that lookup failed silently on any machine without one:
`initialize()` returned normally in the error state, and the Engine Lab could only
report the contract violation `Bad state: initialize returned with state error`
instead of the cause.

This was reproduced on the dev3 source on Linux and Windows CI and compared with
the fixed source on the same runners. dev4 resolves the executable explicitly —
a configured path or `CRISPCHESS_STOCKFISH_PATH`, the bundled Android asset,
`PATH`, then well-known install locations — and, when none exists, reports that
the engine runtime is not installed, with platform-specific instructions
(for example `winget install Stockfish.Stockfish` on Windows or
`sudo apt install stockfish` on Linux). A downloaded Stockfish can also be added
as a custom UCI engine as before.

## One initialization contract for every engine

Stockfish (native, iOS, web), Lynx, custom UCI engines and the model engines
share one start-up contract: `initialize()` returns only when the engine is
ready; otherwise it throws a structured diagnostic with the engine, requested
and detected version, platform, backend, stage, failure kind, cause, exit code,
stderr tail and duration. Concurrent and repeated starts, retries and disposal
during start-up are deterministic. A legitimate backend fallback is recorded,
not hidden. A UCI executable that exits immediately no longer raises an
unhandled "Broken pipe" exception.

## Engine Preflight

The Engine Lab now checks every selected engine before a benchmark: platform,
runtime, initialization, readiness, identity, options, first search, legal move
and cleanup. Each engine gets a card with its status (passed, warning, failed,
not supported here, not installed, timed out, cancelled), expandable and
copyable diagnostics, and retry. Nothing is downloaded without consent. Results
go stale when the engine, its options, the platform, the benchmark settings or
the app build change. A run can continue with the passed engines only after the
results have been reviewed, and the engines left out are listed in the run.
Run reports and the Stability Probe name the structured root cause and redact
personal paths.

## Validation

Release assets are built and structurally verified by the release workflow.
CI builds official Stockfish `sf_16` from source at a pinned commit (validated
NNUE net, never committed or bundled) and runs it on Linux x86-64 through the
built-in adapter, Engine Preflight and the custom-UCI path. Deterministic
fake-process tests cover missing, non-executable, crashing, silent and
misbehaving engines in Linux CI. See the PR and the audit log
(`docs/audit/2026-11-02-engine-initialization-dev4.md`) for exact run IDs, the
platform matrix and limitations.

## Known limitations

- Genuine Stockfish 16 was executed in CI on Linux x86-64 only. Windows, macOS,
  Android, iOS and Web were compiled and tested with fakes, not verified with a
  real Stockfish 16 on those platforms.
- iOS uses the user-downloaded stockfish.js 10.0.2 (Stockfish 10) and reports it
  as such.
- Smoke games are not rating calibration. No absolute Elo is advertised without
  a compatible declared anchor.
- The iOS IPA is unsigned. App Store/TestFlight submission and external signing
  are not part of this GitHub prerelease; the App Store workflow no longer runs
  for development tags.
