# CrispChess Extended v2.3.2-dev7 (prerelease)

This is a development prerelease, **not** the stable v2.3.2 release.

v2.3.2-dev7 ships Hardware Protection, benchmark-stability and Live Board
improvements, plus the correctness fixes landed in PR #15 (merge commit
`b18aed37b3998d0633d7596778902570d63eed50` on `main`).

## Correctness fixes (PR #15)

- **Game phase uses a single move-count unit.** `_getGamePhase()` previously
  compared plies (half-moves) against the threshold when a game had history
  but the FEN full-move number when a position was loaded from FEN, so
  equivalent positions were classified differently (opening vs middlegame).
  Both paths now convert to full-moves (`floor(plies / 2) + 1`) before the
  threshold comparison, so history-played and FEN-loaded positions agree.
- **Calendar dates are strictly validated.** `consecutiveDayGap()` accepted
  any day 1–31, so impossible dates such as `2025-02-29` or `2026-02-30`
  were silently normalized into the next month and shifted the daily-login
  streak. Impossible dates now round-trip check through `DateTime.utc` and
  are rejected (returning `null`, which resets the streak through the
  existing corruption path).
- **Tactical pin/fork detection actually runs.** `move_analyzer`'s pin and
  fork detectors previously received an empty move list on every call (the
  square index was passed where an algebraic key was expected, and
  single-square generation only emits for the side to move). A `_movesFrom`
  probe flips the probe's side to move to the piece's colour and asks for
  pseudo-legal attacks, so Bb5-pins and Nc7-forks are detected for the first
  time. The fork test position now uses black-to-move (the knight gives
  check), which is the only form the library accepts.
- **Opening-book legality proven.** Every book entry's offered UCI is
  re-checked on a fresh probe from its own position, so a typo in the table
  can never hand the game an illegal best move.
- **PGN `[FEN]` round-trip.** Moves are validated against the tagged
  position (not the standard start), and FEN-start games reload onto the
  same position; genuinely illegal moves are rejected.
- **Bench PGN has one header block.** `BenchGame.movetext` is now the
  movetext alone (text after the first blank line), so `pgnDocument()` and
  `GameResult.pgn` no longer duplicate the header block.
- **Daily-login streak and annotation completion hardened.** A fresh game's
  zero `scoreBefore` no longer blocks evaluation completion, and corrupt
  streak data resets instead of throwing.

## Validation

- CI (Analyze & Test), Release builds, Engine Lab and all platform builds
  green on PR #15 head `1d8059e` and on the merge commit `b18aed3`.
- `flutter analyze` and `flutter test` run in GitHub Actions; this sandbox
  has no Flutter/Dart SDK, so nothing here claims behaviour CI did not
  produce.
- Release assets are built and structurally verified by the release
  workflow (`tools/verify_release_assets.py`, fail-closed).

## Known limitations

- CI is the only runtime evidence; no Windows/macOS device claim is made
  from CI. Mobile builds are build-only; real-engine execution jobs run on
  Linux x86-64 (Stockfish 16) and Frozenight WASM.
- The iOS IPA is unsigned; App Store/TestFlight submission and external
  signing are not part of this GitHub prerelease.
- HuggingFace model weights are labelled unpinned and unhashed because the
  project publishes no digests for them here.
