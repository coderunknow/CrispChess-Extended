# CrispChess Extended v2.3.2-dev5 (prerelease)

This is a development prerelease, **not** the stable v2.3.2 release.

dev5 makes the Engine Lab choose its own benchmark. You pick the engines, the
conditions, a statistical objective and a budget; CrispChess picks the
opponents, openings and game counts, and explains every decision in the UI and
in the saved report.

## Ratings you can defend

Every interval in the Lab now states where it came from.

- **Joint fit.** Ratings are one Bradley–Terry fit, and the uncertainty is the
  joint observed-Fisher covariance rather than a per-engine number. Comparing
  two engines uses the joint contrast variance `Var(A-C)`, never
  `sqrt(SE_A² + SE_B²)`. That matters: when A and C are measured only through a
  common opponent B, the contrast variance is *larger* than independence
  implies (measured: 6035 vs 3353 Elo² on a three-engine chain), because the
  shared opponent correlates them.
- **Opening-cluster bootstrap.** The primary interval resamples whole openings,
  keeping each colour-reversed pair together. Ten games on one opening are one
  unit of evidence, not ten. Percentile intervals are reported per engine and
  per pair, with a max-statistic simultaneous interval for the comparison set
  you asked for.
- **Failure is reported, not smoothed.** Replicates that are disconnected,
  singular, non-converged or separated are counted. More than 5% failures, too
  few valid replicates, or fewer than 20 independent opening clusters makes the
  report unreliable, and an unreliable report can never satisfy a precision
  objective. A perfect record is reported as separated — its interval rests on
  the draw prior, not on data — instead of being given a confident-looking SE.
- **Honest fallback.** A document stored before dev5 has no covariance. It is
  shown with the conservative Cauchy–Schwarz bound `SE_A + SE_B` and says so;
  it is never silently replaced by the independence formula.
- **Calibration.** A declared Elo anchor now propagates its own published
  uncertainty into the calibrated interval, and warns when the anchor states
  none.

## The scheduler picks the games

- A connected **pilot** (spanning tree over your targets and the selected
  opponents, one colour-reversed opening unit per edge) establishes a connected
  comparison. Reaching the 20-cluster minimum is the adaptive phase's job, so a
  small budget buys a small-but-valid pilot instead of an error.
- Each further unit is chosen by exact Fisher variance reduction per *measured*
  millisecond — `w(cᵀCu)²/(1 + w uᵀCu)` — weighted by the remaining precision
  gap, with a bonus for a globally new opening while clusters are scarce and a
  penalty for unstable engines.
- It stops on a reliable completed bootstrap that meets the objective, or on
  your budget. When the budget ends first the report says the objective was not
  achieved and how many more games the current trend suggests. It does not
  round a failure up to a success.
- Targets, opponent candidates and participants are three different lists.
  Unselected candidates are recorded separately and never enter the model.
- Every decision is logged with its reason and stored with the run.

## Verified engine downloads and one storage root

- One storage location, chosen in Settings. Desktop uses the directory you pick.
  Android keeps executables in app-private storage (the platform cannot execute
  files from shared storage) and says so. iOS uses its sandbox. The web has no
  filesystem and reports browser-managed Cache Storage rather than a fake path.
- Downloads are HTTPS-only, redirects must stay on HTTPS, transfers have a size
  cap, land in a `.part` file, are hashed, and are installed by atomic rename.
  Concurrent requests for the same artifact are coalesced.
- **A hash published by the project is different from a hash computed after
  download.** Lynx 1.11.0 publishes SHA-256 values and the installer verifies
  against them. No other artifact is claimed to be upstream-authenticated, and no
  checksum is invented anywhere. The Engine Manager labels what it actually
  checked, in these words: `published SHA-256`, `local SHA-256
  (not upstream-authenticated)`, or `size/content-length only (no checksum
  available)`.
- Stockfish is **not** offered as an in-app download. Its `sf_16` release
  publishes per-platform tarballs but every asset's digest is `null` upstream,
  so the app would be downloading a binary it cannot authenticate and then
  executing it. The adapter locates a Stockfish you installed yourself, and the
  Engine Manager says so instead of showing a button that cannot work. (The
  catalog entry previously pointed at the release *page* and could never
  resolve; it is now explicitly source-less rather than silently broken.)
- Lynx's archive is checksum-verified, extracted into a staging directory, and
  only then installed; a failed extraction no longer leaves a binary that
  `isDownloaded()` would accept next launch.
- Moving the storage root copies and verifies before anything is removed,
  **never deletes the old tree**, and resumes an interrupted move on the next
  launch.

## Defect fixes

- `ratingsCsv()` declared `std_err` twice and emitted one value, shifting every
  later column.
- Aborted games stored the suite id as `openingId`.
- `targetStdErr` — a standard error — was announced to users as "±N Elo". The
  report now shows interval half-widths and names the method.
- `customEnginesSupported` claimed iOS could execute a downloaded binary.
- The built-in opening suites topped out at 16 openings, too few for a cluster
  bootstrap. `cluster-40` adds 40 independently validated lines.
- A run holding an infinite uncertainty could not be saved at all: JSON has no
  `Infinity` and `jsonEncode` threw. Non-finite values are stored as `null`
  with a marker on the containing object.

## Validation

- `tool/bench/verify_cluster_bootstrap.py` re-derives the information matrix,
  the clustered bootstrap and the simultaneous interval **independently** of
  the Dart code and checks recovery, the necessity of the joint covariance,
  colour balance, bootstrap calibration against the true sampling SD, Fisher
  coverage (Wilson lower bound) and simultaneous coverage. It runs in CI on two
  seeds.
- `flutter analyze` and `flutter test` ran in GitHub Actions on the merge
  commit. They cannot be asserted from inside the commit they test — a file
  cannot contain the result of a run that starts after it is written — so the
  PR conversation carries the exact commit and run for each result.
- Release assets are built and structurally verified by the release workflow
  (`tools/verify_release_assets.py`, fail-closed).

## Known limitations

- CI is the only runtime evidence. There is no Flutter/Dart SDK in the
  authoring environment: `flutter analyze`, `flutter test` and the platform
  builds ran in GitHub Actions, and nothing here claims behaviour CI did not
  produce. The PR links each result to the commit it ran on.
- Windows, macOS, Android and iOS are **build-only** for the Lab changes. The
  real-engine jobs that execute engines run on Linux x86-64 (Stockfish 16 built
  from pinned source) and on the Frozenight WASM job.
- A precision objective is a statement about the opening clusters actually
  played. It is not a claim that the engines' true strengths are within that
  interval for all openings.
- Smoke games are not rating calibration. No absolute Elo is advertised without
  a compatible declared anchor.
- The iOS IPA is unsigned. App Store/TestFlight submission and external signing
  are not part of this GitHub prerelease.
- HuggingFace model weights (Maia3, Lc0, ChessMamba, Searchless, Chess LM) are
  labelled unpinned and unhashed because the project publishes no digests for
  them here.
