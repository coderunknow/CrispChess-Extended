### Security

- Downloads are HTTPS-only. Verified at three layers: the manager rejects a
  non-HTTPS entry URL (`engine_download`), `streamToFile` rejects a non-HTTPS
  URL before opening a socket, and each redirect hop is re-checked and must stay
  on HTTPS. The redirect guard was **unreachable** before this audit (§2 #6).
- Size limits are enforced from the declared length and again while streaming; a
  truncated or overflowing transfer deletes its partial file.
- Archives are extracted into a staging directory that is now removed on every
  exit path, and only then installed by copy.
- Lynx binaries are verified against the SHA-256 values Lynx publishes. No
  checksum is invented for any other artifact, and the UI distinguishes a
  published hash from a local one.
- Path traversal is refused twice: `_safe()` sanitises component ids, and
  `storageRemoveEngine` refuses any resolved path outside the managed root.
- Migration copies with `followLinks: false` and never deletes the source tree.

## 4. Limitations and unverified claims

- **No Flutter/Dart SDK in the authoring environment.** Dart compilation,
  `flutter analyze`, `flutter test`, the platform builds and all real-engine
  runs are evidenced by GitHub Actions on the final pre-merge commit. No behaviour is
  claimed that CI did not produce.
- **Windows, macOS, Android and iOS are build-only** for the Lab changes.
  Engines were executed on Linux x86-64 (Stockfish 16 built from pinned source)
  and on the Frozenight WASM job.
- The Windows PowerShell extractor fix (`6470956`) is covered by a unit test of
  the quoting and a staging-cleanup test, but the actual `Expand-Archive` call is
  not executed in CI: the Windows job builds, it does not run the app. The
  defect is therefore verified by construction and inspection, not by
  observing a successful extraction on Windows.
- A precision objective describes the opening clusters actually played. It is
  not a claim about all openings.
- Smoke games are not rating calibration; no absolute Elo is advertised without a
  compatible declared anchor.
- The iOS IPA is unsigned. App Store/TestFlight submission and external signing
  are out of scope.
- HuggingFace model weights remain unpinned and unhashed (the project publishes
  no digests for them).
- `Deploy Web` fails at its `Deploy to Vercel` step. This is **pre-existing and
  unrelated**: the same job failed identically at base `09ce482` (run
  41596124411), and the failing step is a repository secret. The GitHub Pages
  push in the same workflow succeeded.

### Round four (8 findings on `ba6f3d1` -> fixed in `495a841`..`e61daea`)

   a tree-sitter **syntax** check. It proves a file parses; it cannot resolve a

   a full CI matrix on the exact SHA rather than by local confidence.
